## 0. 给「下一个 AI」的 30 秒速读

- **一句话**：一个 LangChain AI Agent 内核（能调用工具、多步执行），外面套了一只 Electron 桌面宠物；桌宠支持换皮肤，而「皮肤」= 外观 + LLM 人设 + 固定反应，用户可上传图片自创皮肤（图片经后端 AI 抠图去背景）。
- **三层架构**：`Electron 客户端 (HTTP) → FastAPI 后端 → LangChain Agent → LLM 云 API`。
- **文件地图**：

| 路径 | 职责 | 关键点 |
|------|------|--------|
| `src/config.py` | 构建供应商无关的 LLM 客户端 | `load_dotenv` + `ChatOpenAI(base_url=...)` |
| `src/tools.py` | Agent 的 5 个工具 | docstring 即工具说明；AST 计算器；路径沙箱 |
| `src/agent.py` | 组装 Agent | `create_agent`；`build_agent(system_prompt=None)` 支持运行时注入人设 |
| `src/cli.py` / `main.py` | 命令行入口 | 多轮记忆 |
| `server.py` | FastAPI 后端 | `/chat`（按皮肤注入 persona）、`/remove-bg`（抠图）、`/reset` |
| `desktop-pet/main.js` | Electron 主进程 | 透明全屏窗口、鼠标穿透、全局快捷键 |
| `desktop-pet/renderer.js` | 前端逻辑 | 拖拽、聊天、换肤、抠图、人设卡导入导出 |
| `desktop-pet/skins.js` | 皮肤数据 | 外观 + persona + reactions |
| `deploy/` | 部署 | setup.sh / systemd / 文档 |

- **本地跑**：后端 `uvicorn server:app --port 8000`；桌宠 `bash desktop-pet/start.sh`。
- **改后端地址**：`desktop-pet/renderer.js` 第一行 `BACKEND`。

## 1. 各功能实现详解

### 1.1 Agent 内核（ReAct + Tool-calling）

**做了什么**：给一句自然语言，Agent 自己决定调哪个工具、调几次、何时给最终答案。

**怎么实现**：用 LangChain 1.x 的 `create_agent`（底层 LangGraph），它内部就是一个「LLM 思考 → 调工具 → 把工具结果喂回去 → 再思考」的循环（ReAct 模式）。

```python
# src/agent.py
from langchain.agents import create_agent
agent = create_agent(model=llm, tools=ALL_TOOLS, system_prompt=...)
result = agent.invoke({"messages": [...]})
reply = result["messages"][-1].content
```

**关键设计**：
- **工具说明就是 docstring**。`@tool` 装饰的函数，其 docstring 会被塞进给 LLM 的工具描述里，LLM 据此判断何时调用。所以 docstring 写得清不清楚，直接决定 Agent 聪不聪明。
- **5 个工具**：`web_search`（DuckDuckGo）、`read_webpage`（requests + BeautifulSoup 去标签、截断 3000 字）、`calculator`、`save_file`、`read_file`。
- **模型可插拔**：`config.py` 用 OpenAI 兼容接口，换 DeepSeek / 通义 / GLM / OpenAI 只改 `.env` 三个变量，不动代码。
- **`temperature=0`**：让工具选择稳定可复现（Agent 不是聊天，要的是确定性）。

### 1.2 安全计算器（用 AST 白名单，不用 eval）

**为什么是亮点**：很多人会图省事用 `eval(expression)` 算数学式——这是个**安全漏洞**，用户输入 `__import__('os').system('rm -rf /')` 就能执行任意代码。

**怎么解决**：把表达式解析成 AST，**只白名单放行加减乘除幂模等运算符**，遇到函数调用、属性访问等一律拒绝。

```python
# src/tools.py
_ALLOWED_OPS = {ast.Add: operator.add, ast.Mult: operator.mul, ...}
def _safe_eval(node):
    if isinstance(node, ast.Constant): return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _ALLOWED_OPS: ...
    raise ValueError("表达式包含不被允许的运算。")
```

### 1.3 文件操作沙箱（防路径穿越）

`save_file` / `read_file` 都用 `Path(filename).name` **只取文件名**，丢掉路径部分，防止 `../../etc/passwd` 这种「路径穿越攻击」逃出 `workspace/` 目录。

### 1.4 把 Agent 包成 HTTP 服务（FastAPI）

**为什么**：CLI 只能自己用；包成 HTTP 接口后，任何前端（桌宠、网页、App）都能调用，这是「从脚本到产品」的一步。

- `POST /chat`：收消息 → 跑 Agent → 回答；用字典按 `session_id` 存多轮历史。
- `CORSMiddleware`：允许 Electron 本地页面跨域访问。
- 进程内**复用同一个 Agent 实例**（懒加载），避免每次请求重建。

### 1.5 ⭐ 换皮肤即换人设（运行时动态注入 persona）

**这是全项目最值得讲的设计之一。**

**需求**：切换皮肤时，桌宠的说话风格（人设）也要跟着变——猫娘傲娇、机器人理性。

**朴素做法（差）**：每个人设建一个 Agent 实例。问题：浪费内存、切换有重建开销、不灵活。

**本项目做法（好）**：Agent **本身不内置人设**，人设作为 `SystemMessage` 在**每次请求时实时拼到消息最前面**。

```python
# src/agent.py：允许「不内置」系统提示
def build_agent(system_prompt=BASE_INSTRUCTIONS):
    if system_prompt: return create_agent(model=llm, tools=ALL_TOOLS, system_prompt=system_prompt)
    return create_agent(model=llm, tools=ALL_TOOLS)  # 不内置，交给调用方

# server.py：每次请求按当前皮肤拼人设
system_text = BASE_INSTRUCTIONS
if req.persona.strip():
    system_text += "\n\n【你的角色设定】\n" + req.persona
messages = [SystemMessage(content=system_text)] + history
```

**好处**：单个 Agent 实例，**切人设是 O(1)、零重建开销**；人设可以是任意文本（甚至用户自创），无需预定义。历史里只存 Human/AI 对话，系统提示每次现拼，互不污染。

### 1.6 ⭐ 透明可穿透的桌面宠物窗口（Electron 最难的点）

**踩坑过程**（很适合面试讲「我怎么 debug」）：

1. **问题一：宠物只能在屏幕下半部分移动。**
   - 原因：最初窗口是个小窗口贴在右下角，宠物在窗口内移动，自然到不了屏幕上方。
   - 解决：把窗口改成**铺满整个屏幕的透明无边框层**，宠物用 JS 在这个透明层里自由定位，于是能跑到屏幕任意位置。

2. **问题二：透明层铺满全屏，会挡住下面所有桌面操作（点不到图标）。**
   - 解决：用 Electron 的 `win.setIgnoreMouseEvents(true, { forward: true })` 让窗口**默认鼠标穿透**；再在 `mousemove` 里用 `document.elementFromPoint()` 做**实时命中检测**——鼠标移到宠物/输入框等「可交互元素」(`.interactive`)上时才临时关闭穿透，移开又恢复穿透。

```js
// renderer.js：逐帧命中检测，决定这一刻是否接管鼠标
const el = document.elementFromPoint(e.clientX, e.clientY);
const overInteractive = el && el.closest(".interactive");
setIgnore(!overInteractive);   // setIgnore 内部做了去抖：状态没变就不重复调用 IPC
```

3. **问题三：宠物被拖出屏幕找不回来。**
   - 解决：注册全局快捷键 `⌘/Ctrl+Shift+P`，一键把宠物召回初始位置（主进程 `globalShortcut` → IPC → 渲染层 `initPosition()`）。

### 1.7 聊天记录持久化

用 `localStorage` 存对话历史，重启桌宠不丢；双击宠物打开历史面板。前端的「显示」和后端的「记忆」是两套：前端存给用户看，后端 `_sessions` 存给 LLM 做上下文。

### 1.8 ⭐ 用户自创皮肤 + 上传头像 AI 抠图

**皮肤数据结构**（`skins.js`）：

```js
{ id, name, emoji,
  appearanceType: "image" | "svg" | "emoji",  // 渲染层据此决定怎么画
  image,        // 上传图(dataURL)
  persona,      // 喂给 LLM 的人设
  reactions: { greeting, click: [...] } }       // 纯前端的固定台词
```

- **创建**：表单填名字/人设/反应 + 传头像；存到 `localStorage`，与内置皮肤合并进同一列表。
- **分享**：皮肤可导出/导入为 `.json`（人设卡），是「社区」的雏形。
- **抠图（重点）**：见 §2.2。

## 2. 小众问题 & 优化（面试深挖弹药）

> 这一节是「别人简历里没有」的东西，最能体现工程深度。每条都能撑起 3-5 分钟的追问。

### 2.1 LangChain 1.x 迁移坑

最初用 `from langchain.agents import AgentExecutor` 报 ImportError——LangChain 1.x 把旧的 `AgentExecutor` 换成了基于 LangGraph 的 `create_agent`，调用方式从 `executor.invoke({"input": ...})` 变成 `agent.invoke({"messages": [...]})`，返回结构也变了（取 `result["messages"][-1]`）。**教训**：用快速迭代的库要锁版本、读 changelog。

### 2.2 抠图的「三级降级」+ 一个小算法

**背景**：SVG 内置皮肤天生透明；但用户上传的位图自带背景，直接贴会有突兀白方块。

**方案：优雅降级（graceful degradation）**
1. **首选**：前端把图发到后端 `POST /remove-bg`，用 **rembg（u2net 深度学习模型）** 抠图，任意背景都能抠干净。
2. **兜底**：后端不可用（断网/没开）时，前端用 **Canvas 边缘泛洪（flood-fill）** 去背。
3. **最差**：都失败就保留原图，不阻断流程。

**兜底里的小算法（值得讲）**：不是「把所有白色像素变透明」（那样会把人物身上的白也抠掉），而是**从图片四条边界做 BFS 泛洪**，只把「与边界连通、且颜色接近角落色」的像素变透明。这样**主体内部的白色不会被误删**。

```js
// 从所有边界像素入栈，BFS 扩散；颜色差超过阈值就停（认为遇到主体）
if (dr*dr + dg*dg + db*db > tol*tol) continue;
d[i+3] = 0; // alpha 置 0
```

### 2.3 图片存储优化（localStorage 容量）

`localStorage` 只有约 5–10MB。上传的原图可能好几 MB，几张皮肤就爆了。**优化**：上传后用 Canvas **压缩到最长边 256px** 再转 dataURL 存储（抠图前先压到 512 省带宽）。在「清晰度」和「容量」间取了平衡。

### 2.4 2GB 服务器的内存优化

抠图是唯一的内存大户（u2net 推理峰值 ~1GB）。针对 2GB 小服务器做了三件事：
1. **抠图模型可配**：`REMBG_MODEL` 环境变量，服务器设 `u2netp`（模型从 170MB→4MB，内存峰值 ~1GB→~200MB），牺牲一点精度换内存。
2. **懒加载**：模型只在第一次抠图请求时才载入，平时不占内存。
3. **加 swap**：文档强制要求挂 2GB swap 兜底。

### 2.5 国内访问 GitHub 下模型失败

rembg 首次运行要从 GitHub Releases 下 175MB 模型，国内直连经常断。**解决**：用 GitHub 加速镜像（ghfast.top 等）+ `curl -C -` **断点续传** + **MD5 校验**确保文件完整。部署脚本里把这套自动化了。

### 2.6 鼠标穿透的「去抖」

`setIgnoreMouseEvents` 是 IPC 调用，`mousemove` 每秒触发几十上百次，每次都调 IPC 会浪费。`setIgnore()` 里加了状态判断：**只有穿透状态真的变化时才发 IPC**，避免高频无效调用。

### 2.7 部署架构的认知（容易答错的概念题）

「桌宠怎么部署到服务器？」——**陷阱题**。正确答案：桌宠是客户端，装在用户电脑上，**不部署到服务器**；只有后端 `server.py` 上服务器。能答对这点，说明你真懂 C/S 架构，而不是背流程。

## 4. 面试 Q&A 预演

**Q：你这个 Agent 和直接调 LLM 有什么区别？**
A：直接调 LLM 是「一问一答」；Agent 能自己判断「要不要查资料、要不要算数」，自主调用工具并把结果喂回去多轮推理，直到完成任务。核心是 ReAct 循环。

**Q：换皮肤换人设，你是给每个角色建一个模型吗？**
A：不是。那样浪费内存又有重建开销。我让 Agent 不内置人设，把人设作为 SystemMessage 每次请求实时拼到消息最前面，所以单实例就能 O(1) 切换任意人设。

**Q：为什么计算器不用 eval？**
A：`eval` 能执行任意代码，是注入漏洞。我用 AST 解析 + 运算符白名单，只放行加减乘除等，遇到函数调用直接拒绝。

**Q：桌宠怎么做到不挡住桌面又能点？**
A：窗口默认 `setIgnoreMouseEvents(true, forward)` 鼠标穿透，再用 `elementFromPoint` 逐帧检测鼠标是否在可交互元素上，在上面才临时接管鼠标。还做了状态去抖，避免高频 IPC。

**Q：抠图为什么不在前端做就好？**
A：前端 Canvas 只能处理纯色背景，复杂背景抠不干净。所以主路径放后端用 AI 模型，前端 Canvas 泛洪只作为断网兜底，形成降级链。

**Q：2GB 服务器跑得动深度学习抠图吗？**
A：u2net 峰值约 1GB 风险大，所以我换轻量的 u2netp（内存约 200MB）+ 懒加载 + 2GB swap 兜底，稳态只占几百 MB。

**Q：遇到的最大的坑？**
A：（讲 §1.6 桌宠那三连坑，体现 debug 思路）或（讲 §2.5 国内下模型，体现工程务实）。
